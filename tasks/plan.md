## 1. 概览

按可验证的纵向切片建设：先完成词典授权、模型质量和批量架构 Spike，再交付四条文本核心体验，随后加入学习闭环与 TTS，最后用第二语言验证抽象并开放受控 UI 插件。质量评测、成本与可观测性贯穿所有阶段。

## 2. 前置决策

- 评审并确认 [能力地图](../docs/CAPABILITY_MAP.md) 的模块边界与顺序。
- 选定有合法授权的双语词典/词库；这是 MVP 的硬阻塞项。
- 确定首发地区、数据驻留、可用模型供应商和预算。
- 决定 MVP 是否需要账号；当前计划以匿名会话 + 短期任务记录起步。
- 评分采用产品内部 100 分学习量表；若要对齐雅思/托福，需单独定义标准和数据。

## 3. 交付策略

### 里程碑 A：验证和基础（第 1–2 周）

- 批准 PRD、技术设计和 ADR。
- 建立 monorepo、契约、数据库/队列和观测基线。
- 词典与至少两个模型供应商完成 Spike；黄金集和评测工具可运行。

检查点：授权、质量、成本和部署区域全部可行；否则调整数据源/供应商后再进入 MVP。

### 里程碑 B：文本 MVP 纵向切片（第 3–6 周）

1. 单词查询 + 词性/全部标准义项。
2. 基于义项的例句。
3. 句子评分、定位、纠错和自然改写。
4. 屈折变化与派生词族。
5. 20 项混合批量、SSE、部分成功、取消和重试。
6. 响应式 UI、反馈、能力发现和 P0 质量门槛。

检查点：四个核心流程与批量流程 E2E 通过，黄金集、延迟、成本、安全和无障碍达到 PRD。

### 里程碑 C：学习闭环与语音（第 7–10 周）

- 账号/历史、生词本、CEFR 偏好和复习。
- 接入 TTS，完善播放、缓存、音色/语速和合规提示。
- 质量与成本运营后台、段落分析和导出。

检查点：真实用户学习闭环可测，TTS 质量/延迟/隐私通过专项验收。

### 里程碑 D：第二语言（按语言 4–8 周）

- 新语言包、词典/形态/评分/TTS 适配。
- 母语专家黄金集和抽检。
- 证明无需复制核心业务代码即可上线。

### 里程碑 E：UI 插件平台（4–6 周）

- 先发布声明式主题和受控槽位，再评估代码插件。
- 完成权限、沙箱、签名/来源、兼容、禁用和审核。

## 4. 依赖关系

```text
文档批准
  ├─ 词典授权 Spike ─ lexical slice ─ examples/forms ─┐
  ├─ 模型评测 Spike ─ model gateway ─ sentence review ├─ batch/UI ─ MVP gate
  └─ repo/contracts/runtime ─ queue/SSE/observability ──┘
                                                        ├─ accounts/TTS
                                                        ├─ second language
                                                        └─ UI plugins
```

词典和模型 Spike 可并行；前端可在契约批准后用 fixtures 并行开发；数据库迁移、共享契约和状态机必须顺序推进。

## 5. 验证检查点

### Checkpoint 1：设计批准

- [ ] 能力地图、PRD、技术设计和 ADR 状态从 Proposed/Draft 更新为 Accepted/Approved。
- [ ] 开放问题有负责人和截止日期。

### Checkpoint 2：基础可运行

- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` 全部通过。
- [x] 一个 fixture 任务可从 API 入队、被 Worker 处理并通过 SSE 返回。
- [ ] Trace 能关联 run、item、队列与外部调用。

### Checkpoint 3：核心文本闭环

- [ ] 四个核心功能的单条 E2E 通过。
- [ ] 20 项混合批次部分失败不影响其他项目，顺序保持。
- [ ] 黄金集质量达到 PRD 门槛。

### Checkpoint 4：MVP 发布准备

- [ ] 安全/隐私/词典授权、可访问性和故障演练完成。
- [ ] 模型升级/回滚、供应商降级、队列恢复和预算告警演练通过。
- [ ] 产品、研发、QA 对 P0 验收签字。

## 6. 风险与缓解

| 风险             | 影响         | 缓解                                                       |
| ---------------- | ------------ | ---------------------------------------------------------- |
| 词典授权谈判延期 | 阻塞核心 MVP | 第 1 周并行评估两个合法候选；不以 LLM 临时替代事实源       |
| 模型评分不稳定   | 用户不信任   | 固定量表/版本、黄金集、多模型评测、置信度和人工抽检        |
| 批量成本高于预期 | 无法商业化   | 20 项上限、并发/预算、缓存、模型分级路由、逐项取消         |
| 模型/区域不可用  | 任务失败     | 两个适配器、健康探测、固定可替代路由和 503 明确失败        |
| 扩展抽象过早     | 工期膨胀     | MVP 只交付端口、能力清单和 disabled 实现；运行时按阶段建设 |

## 7. 发布与回滚

- MVP 先内部 → 5% 灰度 → 25% → 100%，每级观察质量、失败率、延迟和成本。
- 模型、提示词、量表、词典版本和语言包独立配置版本，可快速回到上一已评测组合。
- 应用回滚不能回滚已经提交的数据结构；数据库采用向前兼容迁移和 expand/contract。
- 质量护栏下降、成本异常或严重事实错误时自动停止扩大流量。

## 8. 尚不承诺的排期

周数是单个小型全栈团队的初步估算，不含词典商务授权、法务审批、模型采购或母语专家排期。团队规模和这些外部依赖确认后再形成承诺日期。
