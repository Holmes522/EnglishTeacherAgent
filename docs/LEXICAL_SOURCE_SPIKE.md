## 结论与关键约束

现有产品需要英语→中文义项、来源/版本可追溯，并保存任务结果以支持刷新恢复。当前只有 fixture 进入持久化链路。不能仅因为获得 API key，就推定有权保存词典响应、结果快照、SSE 事件、备份或测试基准。

公开资料证实 Cambridge 与 Oxford 都有双语能力，但普通访问许可不能直接视为本项目所需的存储许可。应先明确预算与来源路线，再取得允许目标用途的授权；本报告不是法律意见，也不代替具体合同审查。

## 必须先关闭的架构问题

技术设计 §14 的词典长 TTL 缓存是受授权约束的设计设想，不是现成许可。保留 7 天也不会自动满足第三方权利要求。只禁用 Redis 缓存仍不足以解决 PostgreSQL 结果、run_events 和备份的存储问题。

接入前必须有明确决策：

1. 获得允许当前结果持久化、缓存、测试快照与适用教学生成用途的许可；或
2. 选择经审查可用于这些用途的数据包，固定其版本、摘要和署名方式；或
3. 若只能实时展示而不能保存，单独评审并修改恢复/历史/SSE 设计，不能静默丢失原有能力。

本轮保持服务行为不变，不抓取词典网页，不保存供应商释义，不把资料中的未证实字段当成契约承诺。

## 100 项探针与评测方法

输入清单：[lexical-probes.json](../tests/golden/lexical-probes.json)。10 类、每类 10 项，含常见词、多义词、词形、功能词、派生、拼写变体、短语、领域词及边界与异常输入。`probes` 对象的键是显式固定 ID，后续重排或增删不得复用历史 ID。它是本项目编写的查询探针，不是含标准答案的黄金集，也不宣称 100 项全部应被收录。

评测应直接调用词典适配器，避免当前 AUTO 输入解析把短语路由为句子影响词典覆盖率。用户流程中的短语意图另行验收。

得到许可与可用样本后，对每个候选固定数据集、版本、查询参数、适配器版本和运行日期，逐项记录：

- `probeId`、原输入、实际查询词、命中/未收录/请求失败/未测；这些状态不得互相混用。
- 中文义项、词性、源 ID、版本标识、形态与词族字段是否存在；空值标记缺失，不由 LLM 补写。
- 原始结构到 WordAnalysis 的字段路径与变换规则；稳定 ID 不能仅来自数组位置。
- 每项延迟、HTTP 状态、调用数和已知计费单位；不记录 key 或供应商原始错误。
- 经授权的基准人工复核义项遗漏、错配、可追溯性与异常输入处理。只有许可允许时保存内容快照。

分别报告命中率、字段覆盖率、人工核对结果及错误率。有效输入探针分母为 97；只排除 `coverageExclusions` 明列的 1 个合成 OOV 和 2 个拼写错误，大小写、全角字符、重音字符及罕见词仍参与有效输入覆盖率。它是按查询探针计数而非去重 lemma 计数，同时按组报告以呈现规范化问题。调用失败不能算“未收录”，Sandbox 不可查项应记“未测”；存在未测项时不发布完整覆盖率。本轮真实调用数为 0，覆盖率、延迟和成本均为未测，不能填 0% 或通过。
