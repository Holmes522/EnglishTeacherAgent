## 1. 产品概述

English Teacher AI Agent 是一个面向中文用户的交互式英语学习助手。用户可以输入一个或多个单词、英文句子，或直接提出学习要求；系统识别每个输入项目的类型和意图，提供可信的词义/词性、例句、词形与词族信息，以及可解释的句子评分和纠错。

产品不把通用大模型当作词典。标准词义、词性和规则词形来自可追溯的语言数据源；大模型承担意图理解、教学解释、例句生成和自然度分析。这样既保留自然对话体验，也降低漏义、幻觉和评分漂移。

## 2. 产品目标

### 2.1 目标

- 用户在一次对话中完成“查词—看例句—理解词形—写句子—获得反馈”的闭环。
- 单条和批量输入使用同一套交互模型，批量任务逐项返回并允许部分成功。
- 反馈可解释、可定位、可复现，不只给一个分数。
- 模型供应商可更换、可组合、可降级，不让业务逻辑绑定某个模型 ID。
- 从第一版开始保留语音、多语言和界面插件的稳定扩展边界。

### 2.2 非目标（MVP）

- 不代替专业考试机构给出官方等级或正式成绩。
- 不承诺覆盖某个词在所有时代、方言、行业中的无限义项。
- 不在 MVP 实现实时语音对话、发音打分或语音识别。
- 不在 MVP 开放第三方任意 JavaScript 插件。
- 不在 MVP 建设完整课程、直播课堂、教师后台或社交社区。

## 3. 用户与场景

### 3.1 暂定核心用户

在目标年龄与学习目的尚未确认前，MVP 按 CEFR A2–B2 的中文母语成人/学生进行设计，界面避免幼儿化，也不假定用户熟悉语法术语。

### 3.2 典型场景

1. 用户输入 `run`，希望看到不同词性、全部标准中文义项与例句。
2. 用户输入 `resilient` 并问“有什么变形”，希望看到形态变化与常见派生词族。
3. 用户输入 `He go to school yesterday.`，希望得到分数、错误定位、解释和正确句子。
4. 用户粘贴 8 个单词和 3 个句子，希望系统逐项处理且保持原输入顺序。
5. 用户在结果上点击播放，听到单词或英文例句；该能力在第二阶段实现，但首版数据结构和 UI 槽位已准备。
6. 用户未来选择日语等其他被学语言，产品沿用相同外壳但加载不同语言包与评分策略。

## 4. 核心概念与规则

### 4.1 输入项目

一次提交称为一个“学习请求”，其中可包含多个“学习项目”。学习项目类型：

- `WORD`：单个词或词组。
- `SENTENCE`：一个需要分析的完整句子。
- `INSTRUCTION`：用户对一个或多个项目的明确要求，例如“请列出这些词的形容词形式”。
- `UNKNOWN`：无法可靠判断的输入，需要提出澄清或给出可选操作。

### 4.2 意图

- `LOOKUP`：查词义、词性和发音信息。
- `EXAMPLES`：生成例句。
- `REVIEW`：评判并修正英文句子。
- `WORD_FORMS`：列出屈折变化与派生词族。
- `AUTO`：系统按内容类型选择默认组合。

默认规则：仅输入单词时执行 `LOOKUP + EXAMPLES`；仅输入英文句子时执行 `REVIEW`；用户明确指定意图时，以明确意图优先。

### 4.3 “所有中文意思”的产品定义

“所有”指选定词典数据版本中的全部标准义项，按词性分组，并标注常用度、语域或专业领域（数据源具备时）。结果必须显示词典数据版本或来源标识。大模型可以改写解释帮助理解，但不得创造词典中不存在的义项。

对专有名词、拼写错误、新造词、俚语或词典未收录内容，系统应明确标注“词典未收录/可能是……”，不能伪装成完整释义。

### 4.4 “所有变化”的产品定义

输出分成两类，避免把规则变化和词族混为一谈：

- 屈折变化：复数、第三人称单数、过去式、过去分词、现在分词、比较级、最高级等。
- 派生词族：可验证的名词、动词、形容词、副词及常见否定/前后缀形式。

不是每个单词都能自然地转成所有词性。不存在或极不常用的形式必须显示“无常用形式”，不得强行造词。

## 5. 功能需求

优先级使用：P0（MVP 必须）、P1（近期）、P2（后续）。

### 5.1 输入、识别与对话

#### FR-INTAKE-001 自动识别

- 优先级：P0
- 系统识别单词、词组、句子、混合批量及明确指令。
- 识别置信度低时，不执行高风险猜测；返回识别结果并询问用户选择。
- 保留原始输入和规范化输入，展示结果时使用原始顺序。

验收：

- 输入 `apple` 被识别为 `WORD`。
- 输入 `I went home.` 被识别为 `SENTENCE`。
- 输入每行一个单词/句子的混合内容时，能拆成独立项目。
- 引号、编号、项目符号和多余空白不会破坏拆分结果。

#### FR-INTAKE-002 显式意图优先

- 优先级：P0
- 用户说“只给例句”“不要评分”“列出词形”时，系统按要求执行，不强制附加默认内容。
- 用户后续说“第二个再给我三个例句”时，能关联上一轮第二个项目。

### 5.2 单词释义与词性

#### FR-LEX-001 全标准义项

- 优先级：P0
- 按词性列出中文义项；同一词性的不同义项分开编号。
- 可用时提供英式/美式音标、重音、可数性、及物性、语域、常见搭配和领域标签。
- 展示事实来源标识和词典版本；没有数据时明确说明。
- 支持大小写规范化，但保留专有名词差异。

验收：

- 多词性词条按名词、动词等分组，义项不串组。
- 不规则词条的词性和义项与选定基准词典一致。
- 词典未收录时不能声称“已列出全部义项”。

#### FR-LEX-002 义项可理解性

- 优先级：P0
- 每个义项可包含一句简明中文释义；难词可附简短英文释义。
- 根据用户水平调整解释难度，不改变词典事实。

### 5.3 例句生成

#### FR-EXAMPLE-001 基于义项造句

- 优先级：P0
- 默认生成 3 个例句，覆盖最常用义项；用户可指定数量、难度、场景和时态。
- 每句包含英文、中文翻译、对应义项 ID 和难度标签。
- 目标词及合理变形要高亮；句子必须自然且与义项匹配。

验收：

- 对多义词，例句标明使用的义项，不把两个义项混在一起解释。
- 用户指定“商务场景、B1、过去时”时，输出符合约束。
- 系统过滤包含明显语法错误或不当内容的例句。

#### FR-EXAMPLE-002 例句再生成

- 优先级：P1
- 用户可以对某个例句请求“更简单/更口语/换场景/再来一个”，只重生成目标项。

### 5.4 英文句子评判、评分与纠错

#### FR-REVIEW-001 结构化评分

- 优先级：P0
- 总分 0–100，并给出四个维度：语法 40、词汇与用词 25、自然度 20、拼写与标点 15。
- 同时给出置信度 `HIGH/MEDIUM/LOW`；存在语境歧义时说明假设。
- 评分是学习反馈，不是官方考试成绩。

#### FR-REVIEW-002 错误定位与解释

- 优先级：P0
- 每个问题包含原文片段、错误类型、中文解释、建议替换和严重程度。
- 错误类型至少覆盖：主谓一致、时态、冠词、介词、单复数、代词、词序、搭配、拼写、标点、表达不自然。
- 不把纯风格偏好标为语法错误；风格建议与错误分开展示。

#### FR-REVIEW-003 正确句子

- 优先级：P0
- 输出“最小修改版”，尽量保留原意和原句结构。
- 可选输出“更自然版”，明确它是改写而非唯一正确答案。
- 原句已经正确时，应明确说明，不做无意义改写。

验收示例：

```text
输入：He go to school yesterday.
必须识别：go 与过去时间不一致。
最小修改：He went to school yesterday.
不得把 to school、yesterday 等正确部分误报为错误。
```

#### FR-REVIEW-004 长文本边界

- 优先级：P1
- MVP 以句子为评分单位。段落输入先分句，逐句评分，并提供段落级概览，但不把平均分冒充正式写作分数。

### 5.5 单词变化与词族

#### FR-FORM-001 屈折变化

- 优先级：P0
- 按原词词性输出适用的规则和不规则屈折形式。
- 每个形式包含标签、拼写和可选简短例句。
- 同形词应显示同形，不以空值代替。

#### FR-FORM-002 派生词族

- 优先级：P0
- 按名词、动词、形容词、副词分组列出经过词库验证的常见派生词。
- 显示常用度/罕见标记和简短中文意思。
- 无常见转换时明确说明；不生成未经验证的新词。

### 5.6 批量与多段处理

#### FR-BATCH-001 混合批量

- 优先级：P0
- MVP 单次最多 20 个项目或 5,000 个 Unicode 字符，以先达到者为准。
- 单词和句子可混合；系统逐项识别并选择相应处理流程。
- 输出保持原始顺序，每个项目有独立状态、错误和重试入口。

#### FR-BATCH-002 渐进返回与部分成功

- 优先级：P0
- 页面显示总进度与逐项进度；完成一项即可展示，不等待整批结束。
- 某一项失败不得使其他项目丢失；批次状态可为 `PARTIAL_SUCCESS`。
- 用户可只重试失败项，重复提交不产生重复记录或费用。

#### FR-BATCH-003 资源控制

- 优先级：P0
- 服务端限制并发、输入长度、输出长度和模型预算。
- 超限时在提交前提示可处理范围，不能静默截断。

### 5.7 模型接入与路由

#### FR-MODEL-001 多供应商适配

- 优先级：P0
- MVP 至少接入两个可配置模型供应商，其中至少一个支持结构化输出。
- 业务层只能依赖统一能力接口，不直接依赖供应商 SDK 类型或模型名称。
- 模型名称、区域、价格、上下文、能力和生命周期由配置/能力注册表维护。

#### FR-MODEL-002 路由与降级

- 优先级：P0
- 根据任务类型、质量、延迟、成本、区域可用性选择模型。
- 主模型超时/限流时可切换备用模型；相同请求最多进行有界重试。
- 每次结果记录模型供应商、逻辑模型别名、提示词版本和词典版本，便于回归，但不向普通用户暴露内部敏感信息。

#### FR-MODEL-003 模型生命周期

- 优先级：P0
- 不在业务代码硬编码“最新模型”别名。
- 生产使用经过评测的固定模型版本/稳定 ID；升级必须先跑黄金数据集并支持回滚。

### 5.8 语音能力准备与后续实现

#### FR-SPEECH-001 MVP 接口预留

- 优先级：P0（仅准备，不生成音频）
- 所有可朗读内容返回稳定 `speakableText`、语言标签、内容类型和建议发音变体。
- 词条结果预留 IPA/音标、英美发音标识和播放控件槽位。
- 定义供应商无关的 TTS 接口，MVP 可使用 `NOT_ENABLED` 实现。

#### FR-SPEECH-002 文本转语音

- 优先级：P1
- 支持单词、例句和修正句播放；允许英式/美式发音、语速和重复次数。
- 音频异步生成并缓存；缓存键包含规范化文本、语言、音色、语速和供应商版本。
- 播放器提供播放/暂停、重播、速度和无障碍标签。
- UI 明确提示声音为 AI 合成。

#### FR-SPEECH-003 未来语音输入与发音评测

- 优先级：P2
- STT、音素/字级时间戳和发音评分使用独立能力接口，不把 TTS 结果模型强行复用。
- 需要单独评估麦克风权限、录音同意、存储时长、儿童隐私和口音公平性。

### 5.9 多语言扩展

#### FR-LANG-001 双层语言模型

- 优先级：P0（架构准备）
- 区分 `uiLocale`（界面语言）、`explanationLocale`（解释语言）和 `targetLanguage`（被学语言）。
- MVP 默认 `zh-CN / zh-CN / en`，不得把三者压成一个 `language` 字段。

#### FR-LANG-002 语言包

- 优先级：P2
- 每种被学语言通过语言包声明：输入切分、词性体系、形态规则、词典适配、评分量表、示例策略、语音能力和区域变体。
- 新语言上线前必须有独立黄金数据集和母语专家抽检，不能只翻译英语提示词。

### 5.10 界面插件扩展

#### FR-PLUGIN-001 插件能力描述

- 优先级：P0（文档与接口预留）
- 核心 UI 使用设计令牌和稳定组件槽位，如 `header`, `composer.before`, `result.card.after`, `sidebar`。
- 插件清单包含 ID、版本、兼容的宿主版本、权限、主题令牌和使用的槽位。

#### FR-PLUGIN-002 受控界面插件

- 优先级：P2
- 第一批插件只支持声明式主题、图标、布局密度和受控卡片扩展。
- 禁止插件直接读取模型密钥、会话 Cookie、其他插件数据或未经授权的学习记录。
- 需要签名/来源校验、权限提示、禁用/卸载、兼容性检查和故障隔离。

### 5.11 历史、反馈与个性化（补充需求）

#### FR-HISTORY-001 学习历史

- 优先级：P1
- 用户可查看、搜索和删除历史；匿名会话按短期保留策略存储。

#### FR-VOCAB-001 生词本与复习

- 优先级：P1
- 用户可收藏词义/例句并进入间隔复习；数据结构记录具体义项，不只记录单词字符串。

#### FR-PERSONAL-001 学习水平

- 优先级：P1
- 用户可设置 CEFR 水平、目标场景和偏好的英式/美式英语；影响解释、例句与建议，不改变事实。

#### FR-FEEDBACK-001 结果反馈

- 优先级：P0
- 每个结果可反馈“有帮助/有问题”，问题可选：释义缺失、例句不自然、评分不合理、纠错错误、其他。
- 反馈进入质量队列，不直接让在线模型从单条反馈自我修改。

## 6. 输出规范

### 6.1 单词结果卡

按以下顺序展示：

1. 原词、规范化词形、音标/发音占位。
2. 按词性分组的中文义项。
3. 默认例句及翻译，对应到具体义项。
4. 屈折变化与词族（用户请求或展开后显示）。
5. 来源、置信度、反馈操作。

### 6.2 句子评改卡

按以下顺序展示：

1. 总分、维度分和置信度。
2. 最小修改后的正确句子。
3. 原文中带位置高亮的问题列表。
4. 更自然版本（可选）。
5. 简短总结与下一步练习建议。

### 6.3 批量结果

- 顶部显示完成数/总数、成功数、失败数和取消操作。
- 每项独立卡片，编号与原始输入一致。
- 允许折叠全部、展开失败项、只重试失败项和导出结构化结果（P1）。

## 7. 异常与边界行为

| 情况 | 预期行为 |
|---|---|
| 空输入 | 禁止提交并给出示例 |
| 只有标点/乱码 | 标记无法识别，不调用昂贵模型 |
| 拼写疑似错误 | 给候选词并请求确认，或在低风险情况下标注假设后处理 |
| 中英混合句 | 允许评改英文部分，说明未评分片段 |
| 多个句子粘在一行 | 可靠分句后逐项处理；歧义时保留为一个段落 |
| 词典无结果 | 明确未收录；可给模型推测但必须标“未经词典验证” |
| 模型拒答/超时 | 展示可重试错误，不伪造结果；其他批量项目继续 |
| 输出结构不合法 | 服务端拒绝并有界重试/降级，不将原始模型 JSON 直接展示 |
| 用户要求不当内容例句 | 遵循安全策略并提供安全替代场景 |
| 同一请求重复提交 | 通过幂等键返回原任务或原结果 |

## 8. 非功能需求

### 8.1 性能（MVP 目标）

- 单项目：P95 首个可见状态更新 ≤ 1 秒；P95 首个内容结果 ≤ 4 秒；P95 完整结果 ≤ 12 秒。
- 20 项批量：2 秒内显示拆分结果和进度；P95 全批完成 ≤ 60 秒。
- 模型延迟不完全可控，因此指标区分排队、内部处理和供应商耗时。
- UI 在 360px 宽度至桌面宽度下可用，批量结果不导致主线程长时间阻塞。

### 8.2 可用性与可靠性

- 月度 API 可用性目标 99.9%（计划维护除外）。
- 批量任务结果至少保存到可完成重试的期限；任务状态机可恢复。
- 所有外部调用有超时、退避、熔断和配额保护。

### 8.3 准确性与一致性

- 词义/词性与基准词典的字段一致率 ≥ 99%；“全义项覆盖率”以选定词典版本计算 ≥ 98%。
- 黄金句子集上的关键语法错误召回率 ≥ 95%，严重误报率 ≤ 3%。
- 同一固定模型、提示词和输入重复评分的总分标准差目标 ≤ 5 分。
- 例句的语法正确率和义项匹配率经自动检查 + 人工抽检达到 ≥ 97%。

### 8.4 安全、隐私与合规

- 默认不收集不必要的个人信息；敏感输入和模型日志采用最小化与分级保留。
- 模型密钥只保存在服务端密钥管理系统，不进入浏览器、日志或插件。
- 用户输入始终视为数据而非系统指令，防止提示注入改变评分规则或泄露系统提示。
- 若产品面向未成年人，需要在上线前增加年龄分层、监护人同意、儿童数据和内容安全专项评审。
- 用户可删除自己的历史和录音；删除流程覆盖数据库、对象存储和合法可删除的缓存。

### 8.5 可访问性

- 核心流程目标达到 WCAG 2.2 AA。
- 错误不能只靠颜色表达；评分图表有文本替代；所有播放控件可键盘操作。

### 8.6 成本

- 每次模型调用记录输入/输出 token、缓存命中、路由决策与估算成本。
- 设置每用户、每批次和全局预算；超过预算时优先降级模型或提示拆分，不静默降低结果完整性。

## 9. 产品指标

### 9.1 北极星指标

每周完成至少一次“输入 → 阅读反馈 → 追问/修正后再次练习”学习闭环的活跃用户数。

### 9.2 核心指标

- 首次请求成功率、批量完全成功率、部分成功率。
- 结果“有帮助”比例及各问题类型比例。
- 句子修正后再次提交率、二次评分提升幅度。
- 单词例句展开率、词形查看率、播放率（语音上线后）。
- P50/P95 延迟、每成功项目成本、模型降级率。
- D1/D7 留存（账号/稳定匿名标识上线后）。

### 9.3 护栏指标

- 词典事实错误率、严重纠错误报率、不安全内容暴露率。
- 模型调用失败率、结构化输出校验失败率。
- 用户删除请求完成时间、敏感日志违规数。

## 10. 分阶段开发

### 阶段 0：需求验证与技术 Spike（1–2 周）

- 确认目标用户、核心场景、词典授权与部署地区。
- 用不少于 300 条初始黄金数据比较候选模型的查错、解释、中文教学和结构化输出。
- 验证 20 项批量的延迟/成本，确定默认模型与降级模型。
- 评审通过能力地图、PRD、技术设计和 API 契约。

退出条件：词典数据源可合法使用；至少两个模型供应商完成 Spike；关键质量/成本目标可实现。

### 阶段 1：文本 MVP（4–6 周）

- 单词全部标准义项与词性。
- 默认/定制例句。
- 句子评分、错误定位、最小修正与自然改写。
- 屈折变化和派生词族。
- 20 项混合批量、渐进返回、部分成功和重试。
- 两个模型适配器、模型路由、基础缓存/限流/观测。
- 响应式 Web、结果反馈、语音/多语言/插件接口预留。

退出条件：P0 验收通过；黄金集指标达标；安全和隐私评审通过；可灰度给内部/小流量用户。

### 阶段 2：学习闭环与语音（3–5 周）

- 账号/历史、生词本、CEFR 个性化和间隔复习。
- 单词/例句/修正句 TTS、英美音与语速控制。
- 更完善的段落评改、导出和学习报告。
- 供应商故障自动降级、成本看板和质量反馈后台。

退出条件：TTS 发音与缓存验收通过；隐私/录音政策就绪；学习闭环指标可观测。

### 阶段 3：第二语言验证（4–8 周/语言）

- 选择一种与英语差异明显的目标语言验证语言包边界。
- 接入对应词典、形态/分词、评分量表和语音。
- 由目标语言专家构建黄金数据与抽检。

退出条件：核心业务无需分叉复制；同一客户端可切换语言包；该语言质量门槛达标。

### 阶段 4：界面插件平台（4–6 周）

- 插件清单、版本兼容、权限、签名/来源、安装与禁用。
- 声明式主题与受控组件槽位；插件崩溃隔离。
- 开发者文档、示例插件、自动兼容测试和审核流程。

退出条件：插件不能越权读取数据/密钥；禁用后恢复默认 UI；宿主升级有兼容策略。

## 11. MVP 总体验收

以下条件全部满足才可称为 MVP 完成：

1. 单词查询、例句、句子评改、词形/词族四个核心流程有端到端自动化测试。
2. 混合 20 项批量能够逐项显示、保持顺序、支持部分成功和失败项重试。
3. 事实型词汇结果可追溯到已批准词典版本，大模型不能覆盖词典事实。
4. 句子评分包含量表、分项、错误位置、原因、最小修正和置信度。
5. 至少两个模型供应商可通过配置切换；主供应商故障演练能降级。
6. 语音、多语言、插件的契约和 UI 槽位已建立，并有 `NOT_ENABLED`/能力发现行为。
7. 性能、质量、安全、成本和可访问性指标达到本 PRD 的 P0 门槛。

## 12. 待确认问题

- 目标年龄和学习目标：校内英语、四六级/考研、雅思托福、职场，还是通用？
- 词典授权预算与“全部义项”的基准词典是哪一套？是否需要短语、习语、专业义项？
- 首发地区、数据驻留和可使用的大模型供应商有哪些限制？
- MVP 是否匿名可用？历史记录保留多久？
- 免费额度、付费模式、单用户每日请求与批量限制是多少？
- 评分是否要对齐 CEFR、雅思/托福写作，还是仅采用产品内部学习量表？
- 是否把移动 App、微信小程序或浏览器扩展纳入第二阶段？
