# ADR-003：单条与批量统一为异步 Learning Run

## 状态

Proposed

## 日期

2026-09-09

## 背景

模型与词典调用延迟和失败率不可控；批量输入需要渐进结果、部分成功、取消和失败项重试。若单条走同步接口、批量另建任务系统，会形成两套状态与错误语义。

## 决策

所有请求创建 `LearningRun`，单条视为一个 item 的 run。`POST` 返回 `202`，客户端用 SSE 获取进度，并用 `GET` 获取最终事实状态。任务通过数据库状态、outbox 和可靠队列驱动，按至少一次执行设计，幂等键阻止重复副作用。

## 备选方案

### 全部同步 HTTP

- 优点：客户端简单。
- 缺点：长批次容易超时，无法可靠恢复、取消或逐项返回。
- 未选原因：不满足批量 P0 需求。

### 单条同步、批量异步

- 优点：单条响应路径短。
- 缺点：两套接口、状态、测试和重试逻辑；行为不一致。
- 未选原因：长期维护成本高。

## 后果

- 客户端需要任务状态和 SSE 断线重连逻辑。
- 即使单条请求也多一次任务创建，但可以立即展示排队/运行状态。
- Worker 崩溃恢复、租约、幂等和 outbox 成为 MVP 基础能力。
