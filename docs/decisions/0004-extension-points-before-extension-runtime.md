# ADR-004：先稳定扩展点，再实现语音、多语言和插件运行时

## 状态

Proposed

## 日期

2026-09-09

## 背景

MVP 暂不实现语音、其他被学语言和界面插件，但如果首版数据结构只围绕中文界面/英语文本/固定 UI 设计，后续会产生破坏性迁移。另一方面，提前实现完整插件或多语言平台会拖慢核心验证。

## 决策

MVP 只交付必要的稳定扩展点：分离 `uiLocale/explanationLocale/targetLanguage`；定义 LanguagePack、SpeechProvider 和 SpeakableContent；UI 使用设计令牌与命名槽位；通过 capability manifest 返回 `NOT_ENABLED`。第三方代码执行、真实 TTS 和第二语言在后续阶段实现。

## 备选方案

### 等需要时再改

- 优点：MVP 代码更少。
- 缺点：公开结果和 UI 容易固化错误假设，迁移影响所有消费者。
- 未选原因：接口准备成本较低，后期破坏代价高。

### MVP 就实现完整平台

- 优点：功能一次到位。
- 缺点：尚无真实扩展消费者，极易过度设计，延迟核心产品验证。
- 未选原因：范围和风险不匹配。

## 后果

- MVP 有少量暂未启用的类型和 UI 槽位，需要契约测试保持稳定。
- 扩展点是提案，可在外部开发者使用前调整；一旦开放插件 SDK，必须执行兼容和弃用策略。
